SS Head Unit Build Plan

A weekend-by-weekend plan to replace the stock MyLink screen with a Raspberry Pi head unit running Android Auto, while keeping steering wheel buttons, climate display, chimes, the Bose amp and the backup camera working.

Ground rules Listen before you talk: keep everything in listen-only mode until messages are understood. Never cut the factory harness. Fuse anything on 12V. Disconnect the battery before unplugging modules behind the dash.

Phase 1 · CAN sniffer

Weekends 1–3

Build a cheap ESP32 sniffer that SavvyCAN treats like a Macchina M2, and see the car's body bus for the first time.

1
Order parts & set up the bench
Target: Oct 17–18
›

Goal: transceiver on order, laptop ready, ESP32 flashing reliably.

Instructions

  1. Pigtail test: multimeter on continuity. Touch one probe to a pin inside the OBD plug (a paperclip helps), the other to each loose wire until it beeps. Pin 1 is the critical one; cheap pigtails sometimes skip it.
  2. Board support: in Arduino IDE, add the Espressif boards URL in Preferences, install “esp32 by Espressif,” and select “ESP32 Dev Module.”
  3. Driver: look at the small chip near the USB port. CP2102 → Silicon Labs driver; CH340 → WCH driver. If the board shows up as a serial port, you're done.
2
Firmware & research while parts ship
Target: Oct 24–25
›

Goal: ESP32RET built and running at 33.3 kbps; schematic drawn; stock system understood on paper.

Instructions

  1. Pins: use GPIO 25 for CAN TX and GPIO 26 for CAN RX. They avoid the ESP32's boot-strapping pins. Record them in sniffer/README.md.
  2. 33.3 kbps timing: the ESP32's CAN clock is 80 MHz. A prescaler of 120 gives 1.5 µs per time quantum; 20 quanta per bit = 33.333 kbps with an 80% sample point. If the firmware won't accept 33333 directly, use:
twai_timing_config_t t = {
  .brp = 120, .tseg_1 = 15, .tseg_2 = 4,
  .sjw = 3, .triple_sampling = false };
  1. Bench test without the car: the ESP32's CAN controller has a self-test mode. If frames you send show up in SavvyCAN, the firmware side is good.
3
Build the sniffer & first contact
Target: Oct 31–Nov 1 (or whenever the transceiver arrives)
›

Goal: see live body-bus traffic in SavvyCAN.

No traffic? Check pin 1 continuity, that mode pins are high, the bit rate is 33,333, and the car is actually awake (accessory on, or open a door). A wrong bit rate shows as bus errors rather than silence.

Phase 2 · Decode the car

Weekends 4–6

Turn raw traffic into a message database, and learn exactly what the stock head unit does.

4
Capture session
Target: Nov 7–8
›

Goal: one clean, labelled log per action.

Instructions

  1. Start each recording, wait 5 seconds, do the action, wait 5 seconds, repeat. The quiet gaps make changes obvious.
  2. Name files by action: 2026-11-07_swcan_swc-vol-up.csv. Note anything odd in logs/README.md.
  3. Keep each log short (under a minute). Small focused logs are far easier to decode than one long one.
5
Decode & find the radio's messages
Target: Nov 14–15
›

Goal: steering wheel, climate, gear and ignition messages decoded; list of messages the radio sends.

Instructions

  1. In SavvyCAN, open the Sniffer window while replaying a log. Bytes that change highlight; that's where the action lives.
  2. Compare each action log against the baseline. An ID that appears only during the action is usually event-driven (buttons); a changing byte in a periodic message is usually state (climate).
  3. Radio fuse test: find the radio fuse in the owner's manual. Record 60 s normally, pull the fuse, record 60 s more. IDs that vanish are sent by the radio, and those are the ones your head unit may need to imitate.
  4. Mark each entry guess, likely or confirmed. Only confirmed messages get transmitted later.
6
Pull the stock unit & map the connectors
Target: Nov 21–22
›

Goal: every pin on the stock connectors identified and measured; dash opening measured.

Instructions

  1. Disconnect the battery before unplugging connectors. Reconnect it only to take live measurements, then back-probe from behind connectors with thin probes; don't pierce wires.
  2. Mic bias: stock unit on, measure DC voltage across the mic wires. Typical GM values are several volts.
  3. Amp input: twisted pairs per channel to the amp suggest analog differential audio. A single thin coax or fiber-optic plug suggests digital, which changes the plan (see decision log).
  4. Camera: a single coax with a few volts of power alongside usually means analog composite video, which is easy to capture with a USB grabber.
Decision point If the amp input is analog and nothing critical breaks with the radio fuse pulled, order the Phase 3 parts now.

Phase 3 · Bench prototype

Weekends 8–10

Build the whole head unit on the desk, driven by recorded car traffic, before anything goes in the dash.

8
Pi bring-up & SocketCAN
Target: Dec 5–6
›

Goal: Pi boots from NVMe, drives the display, and can replay car logs onto a real CAN interface.

Instructions

# /boot/firmware/config.txt (match your module's crystal and IRQ pin)
dtparam=spi=on
dtoverlay=mcp2515-can0,oscillator=8000000,interrupt=25

# then:
sudo apt install can-utils
sudo ip link set can0 up type can bitrate 33333
candump can0

Many cheap MCP2515 modules use an 8 MHz crystal (check the silver can on the board). Many also run the MCP2515 from 5V, so make sure its SPI lines are 3.3V-safe before connecting it to the Pi.
